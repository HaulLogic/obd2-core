# Registry crates.io `obd2-core` 0.2.0 vs local workspace

**Date:** 2026-07-11  
**Purpose:** WS-B1.0 identity evidence (OBD plan F11)  
**Registry baseline:** crates.io `obd2-core` **0.2.0** (cache path used at audit time: `~/.cargo/registry/src/*/obd2-core-0.2.0`)  
**Local package after this note:** **`0.3.0-dev`** (must never claim `0.2.0` while diverging)

## Summary

| Metric | Registry 0.2.0 | Local tree |
| --- | --- | --- |
| `.rs` files under `src/` | 31 | 44 |
| Registry-only files | 0 | — |
| Local-only source files | — | 13 (+ content changes on almost all shared files) |

Cargo pins registry deps by **checksum**. Today’s `haullogic-core` build against crates.io `0.2` is deterministic. The hazard is a **silent API swap** if a consumer switches `version = "0.2"` → `path` / `git` without a **manifest-visible** version change. Local and registry previously both claimed `0.2.0`.

## Themes of local divergence (informational)

- STN adapter, native CAN, richer ELM codec/transport split  
- UDS / DoIP / ISO-TP / framed transport  
- Session discovery  
- Broader protocol/session surface than published 0.2.0  

Published 0.2.0 **already includes** J1939 helpers (`read_j1939_pgn`, `protocol/j1939.rs`); local may still be ahead on framing and discovery. Do not re-plan Phase D as greenfield.

| `obd2-dash` | Git rev pin (historically `94cc681…`); may lag until deliberately rebased onto `0.3.0-dev` identity |

## Reproduce

```bash
REG=$(ls -d ~/.cargo/registry/src/*/obd2-core-0.2.0 | head -1)
diff -rq crates/obd2-core/src "$REG/src"
```

Run from the `obd2-core` repo root after `cargo fetch` of registry 0.2.0.
